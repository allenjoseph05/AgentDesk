## Executable fixture path

The dedicated `adaptive-demo` browser profile runs the real browser -> AG-UI -> Coordinator -> A2A
decision-scoper -> Google ADK fixture agent -> bounded A2UI -> AG-UI submit/skip -> Researcher ->
Analyst -> Verifier path. All services bind to loopback, persistence uses a temporary SQLite
database, and the scoper uses its separately locked virtual environment. The profile reads no model
credential, makes zero provider calls, and costs nothing to run.

The Playwright matrix proves accepted submit and skip paths, duplicate-action replay rejection,
browser abort during scoping, a fresh run after cancellation, persisted history reload, and exact
state rehydration without another AG-UI run. The normal browser suite separately forces a scoper
failure and proves the user can switch to the trusted direct form. Coordinator and scoper suites
retain the lower-level timeout, remote cancellation, disconnect, stale/cross-session submission,
malformed artifact, compiler fallback, and no-rerun recovery assertions.

Run it from a prepared checkout:

```powershell
python scripts/setup_adaptive_intake_e2e.py
npm run test:e2e:intake
```

The setup command installs only the committed scoper lock into `.venv-scoper`. It does not require a
Google account, API key, billing profile, Docker, or PostgreSQL.

## Benchmark result

`fixtures/intake/fixture-evaluation.json` is generated by the same deterministic evidence script as
the original baseline. It executes all 40 predeclared cases. Ten complete controls use the intended
deterministic bypass. Only three ambiguous cases have committed scoper fixtures; the other 27 are
marked `fixture_unavailable` and scored as zero rather than copying targets or inventing outputs.

| Cohort/profile | Cases | Coverage | Quality |
|---|---:|---:|---:|
| Ambiguous direct baseline | 30 | 30 direct captures | 0.2000 |
| Ambiguous fixture candidate | 30 | 3 scoped, 27 unavailable | 0.0500 |
| Complete controls | 10 | 10 deterministic bypasses | 0.8000 |

The required scoped quality was 0.2300. The fixture candidate is 75 percent below the direct
baseline and does not independently score final recommendation usefulness. This is expected from a
three-case protocol fixture; it is useful integration evidence, not evidence that a live scoper
improves decisions.

## Gate decision

| Gate | Result | Evidence |
|---|---|---|
| Valid proposals/surfaces across the full benchmark | Fail | Three fixture cases validate; 27 ambiguous cases have no candidate proposal. |
| Three materially different domain forms | Pass | Technology, procurement, and travel golden fixtures compile through one bounded catalog. |
| Answers change request, analysis, and final output | Partial | Typed request propagation is proven; suite-wide final-output impact is not independently scored. |
| At least 15% ambiguous quality improvement | Fail | 0.0500 candidate versus 0.2300 required. |
| Existing protocol, persistence, cancellation, and recovery suites | Pass | Focused and full CI suites remain required. |
| Accessible input, visible errors, skip, and fallback | Pass | Trusted catalog, static renderer fallback, and manual direct fallback are browser tested. |
| One-call latency/token budget | Fail | Fixture mode uses zero calls; no approved live profile has latency or token evidence. |
| No unresolved high/critical dependency or image finding | CI-gated | Story 8 builds and scans the isolated scoper image; each CI run must remain free of high/critical findings. |

Because every gate did not pass, live mode defaults to the direct `start_research` path. Adaptive
intake requires the explicit browser build flag `VITE_AGENTDESK_ADAPTIVE_INTAKE_ENABLED=true`, while
`adaptive-demo` enables it only for this deterministic evaluation. Story 8 adds local/CI Compose
wiring through an explicit key-free opt-in overlay, but does not add the paid hosted service or claim
default-on production value without a representative live candidate and a new published benchmark
result. See the [rollout evidence](./adaptive-intake-rollout.md).
